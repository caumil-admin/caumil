- logic 0.85 빈틈없고 수치 일치 / 0.7 작은 비약 / 0.5~0.6 눈에 띄는 비약·불일치.
- reliability 0.85 재현 가능한 데이터·설정·통계(반복·신뢰구간·검정) / 0.7 설정 충실, 통계 부족 / 0.5 일부 근거 또는 측정값 없음.
- references 0.85 핵심·최신 15편+ 비교 / 0.7 10~15편 / 0.55 8~10편 / 0.4 8편 미만 / 0.25 서지 오류 다수.
- impact 0.85 군 전반·타 분야 확산 근거 / 0.65 여러 부대·체계 / 0.5 해당 업무 범위.
- novelty 0.85 새 접근·구조 / 0.65 의미 있는 개선·새 조합 / 0.5 조합·적용 / 0.3~0.4 재현·벤치마크.

## 받은 뒤 할 일
1. 전 원고의 세부 요소를 한 표에 놓고 척도를 본다(같은 성격의 원고끼리 같은 세부 요소가 어긋나면 why 의 점수와 함께 고치고 "(척도 보정 M/D — 이유)" 를 남긴다).
2. `grep -l '@' eval/*.json` 으로 이메일이 없는지 본다(P@3 같은 옛 지표 표기는 괜찮다).
3. `./run.sh lint && ./run.sh score && ./run.sh check` 가 0 errors 인지 확인한 뒤 빌드한다.
