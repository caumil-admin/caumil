## 척도(6개 변수 0~1, 0.05 단위) — 원고 텍스트 근거만
- sota(SOTA 실험 수준): 0.3 검증 부족(결과 없음·자체 기준선만·단일 실행) / 0.5 강한 baseline 과 비교하고 공개 또는 통제된 데이터에서 수치 제시 / 0.7 여러 baseline·절제·반복(시드·CI) 또는 공개 벤치마크에서 경쟁력 있는 결과 / 0.85+ 공인 벤치마크에서 SOTA 급 결과와 통계적 뒷받침. 설계·문헌고찰 논문은 0.35 이하.
- orig(프레임워크 독창성): 0.3 기존 방법 재현·적용 / 0.5 일부 구조 개선·새 조합 / 0.7 문제 정의나 구성이 새롭고 차별점이 분명 / 0.85+ 명확한 신규 프레임워크·새 과제 정의.
- hwUse(HW 시연 유용성): 전용 HW 가 없는 순수 SW·데이터 과제는 0.10~0.35(엑셀 관례), 실기기·센서·로봇·단말이 문제 해결 경로에 실제로 쓰였으면 0.5~0.8, 문제 해결에 필수이고 실기기 결과가 있으면 0.8+.
- hwFit(HW–알고리즘 결합도): 순수 SW 는 0.05~0.30(시뮬레이션 구간), 일부 실시간 연동 0.5, 실기기 end-to-end 연동을 측정·시연했을 때만 0.8+.
- stability(라이브 시연 안정성): 0.3 단일 실행·강건성 근거 없음 / 0.5 통제 환경 또는 오프라인에서 일부 반복 / 0.65~0.75 오프라인 실험이되 반복·시드·신뢰구간·민감도 분석이 충실(오프라인만 있으면 상한 약 0.75) / 0.8+ 실기기 반복 구동과 변수 상황(잡음·망 정체·환경 변화)에서의 동작 근거. 결과가 없는 설계·문헌고찰 논문은 0.35 이하.
- delivery(발표 전달력): 원고의 초록·서론·결론에 문제–방법–수치가 짧고 일관되게 드러나는지. 0.5 핵심은 전달되나 장황하거나 수치 불일치 / 0.7 문제·방법·결과가 분명 / 0.85+ 짧고 설득력 있는 서사, 초록·본문·결론 수치 일치, 주장 범위가 증거와 맞음. (발표자료가 아니라 원고로 매깁니다.)
- 계획서(projectMatch same·related)가 있으면 계획서 6개 점수에서 출발해 원고 근거로 올리고 내리며, rationale 마다 "계획서 a→b(±d)" 로 시작합니다. different·none 이면 사전값을 쓰지 않습니다.
- 리스크(블라인드 위반·템플릿 잔재·중복게재·투고처 불일치·서지 오류)는 점수에 넣지 않고 flags 에만 적습니다. high = 투고 전 반드시 고칠 것, mid = 심사에서 지적될 것.
- 짧은 학술대회 논문(정보기술학회)도 같은 척도로 매기되 분량 자체를 감점하지 않고, 근거가 없는 변수만 낮게 줍니다.
